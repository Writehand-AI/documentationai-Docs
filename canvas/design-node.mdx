The **Design node** delivers the **[Page](/outcomes/assessments)** outcome: a completely custom HTML result page at the end of a product. You design the page in Claude using the [connector](/claude-connector/overview), embed `{{ }}` tokens, and the platform resolves them live when your end user views their result.

Reach for it when you want a premium, branded, visual deliverable: a scorecard with dimension bars and a score ring, a personalised report with sections and a CTA, or any result that should feel built just for that person.

<Callout kind="info">Pages are designed and edited **entirely in Claude** — there is no in-app HTML editor. Add the Design node here on the canvas; do the actual design work in your Claude chat.</Callout>

---

## How it works

1. Add a **Page** node to the canvas and connect it below your AI Product (usually via an **AI Agent** node that produces the structured scores/fields).
2. In Claude, ask for the page — e.g. *"design a scorecard results page for my Leadership product."* Claude writes the HTML and applies it with `update_page`.
3. Embed `{{ variable }}` tokens anywhere in the HTML — they're resolved live when a client views the page.
4. Publish. Every client who completes the product receives their own personalised version.

<Callout kind="info">Variable tokens are resolved server-side **at view time**, not at generation time. You can update a live product's page and all future views use the new design, without re-running the AI workflow.</Callout>

## Variable tokens

The Page supports these variable categories, all using the same `{{ category:key }}` syntax:

| Token | Source | Example |
|---|---|---|
| `{{ form:fieldName }}` | A field from the product's intake | `{{ form:company }}` |
| `{{ node:varName }}` | Full text output from an AI node | `{{ node:report }}` |
| `{{ object:varName }}` | A named field inside a structured AI output | `{{ object:score }}` |
| `{{ custom:key }}` | A [workspace variable or brand image](/workspace/variables) | `{{ custom:booking_url }}` |

<Callout kind="tip">Not sure what tokens are available? Ask Claude: *"list the variable tokens for my [product] product"* — Claude calls `get_variables` and returns every token ready to copy. See [Token resolution](/claude-connector/tokens).</Callout>

### Example

```html
<h1>Hi {{ form:firstName }}, here's your report</h1>
<div class="report-body">
  {{ node:report }}
</div>
```

When a client named "Sarah" views the page, she sees her name and her specific AI-generated report — no one else's.

## Multi-page output

A single product can have multiple Page nodes, each a page in the respondent's nav bar — use them to structure a longer deliverable:

- **Page 1** — Executive summary or score overview
- **Page 2** — Detailed analysis or recommendations
- **Page 3** — Next steps and call to action

Each page has its own HTML and can reference any variable in the product. Give each a nav title (in the node's settings panel) and they appear as a nav bar for respondents.

---

## Building your HTML in Claude

Ask Claude to generate the layout and apply it in one step:

> *"Generate a dark-themed premium HTML layout for a leadership readiness report. Use {{ node:report }} for the main content and {{ form:firstName }} in the header. Then apply it to my Leadership Assessment product."*

Claude calls `get_variables` to know what tokens are available, writes the HTML, and calls `update_page` to apply it — returning a demo URL so you can preview immediately.

**Bringing a design from another tool** (Figma export, v0, Gamma, hand-coded HTML)? Paste it into the Claude chat — Claude cleans it (strips scripts and external CSS, fixes layout), proposes which text should become `{{ }}` tokens, and saves it. See [Design custom result pages](/claude-connector/result-pages).

## Nav & ordering (the canvas panel)

Clicking the Page node on the canvas opens a small settings panel. It does **not** contain an HTML editor — the design lives in Claude. The panel lets you:

- **Set the nav title and order** for this page in the respondent nav bar (leave the title blank to hide it).
- See a link to open Claude to create or edit the page.

## Page vs Standard

| | Page | [Standard](/outcomes/standard) |
|---|---|---|
| **How you design it** | Custom HTML + tokens — written in Claude | AI writes the output directly, guided by your instructions |
| **Visual control** | Complete — any layout, charts, branding | Text-based |
| **Best for** | Premium branded layouts, scored result pages | Most products — fast, instant, personalised |
| **Multi-page** | Yes | Single streamed output |

Use **Page** when visual control matters. Use **Standard** when you want the AI to write and deliver the result without a custom design.

## Editing output pages via Claude

Once a product is live, update its Page output from Claude without opening the canvas:

1. **`get_page`** — lists all pages with their IDs and a preview of the current HTML
2. **`get_variables`** — lists every `{{ }}` token available in the product
3. **`update_page`** — replaces the HTML (and optionally CSS) of a specific page
4. **`get_product`** — returns the demo URL so you can preview the change immediately

This is the full conversational editing loop — see [Design custom result pages](/claude-connector/result-pages).
