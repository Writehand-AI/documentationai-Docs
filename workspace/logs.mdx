The Logs page provides an audit trail of significant actions taken in your workspace. Use it to track changes, review who did what, and diagnose unexpected behaviour.

<Callout kind="info">📸 **Screenshot needed:** The Logs page showing a list of log entries with timestamps, action descriptions, and the user who performed the action</Callout>

## What is logged

The log captures workspace-level events including:

- Member invitations sent and accepted
- Role changes and permission updates
- Variable additions, updates, and deletions
- Prompt library changes
- Account settings changes
- API key generation

Not all platform activity is logged — the log captures significant administrative and configuration events, not every product interaction or response submission.

## Reading the log

Each log entry shows:

- **Timestamp** — when the action occurred
- **Action** — a description of what happened
- **User** — who performed the action
- **Details** — additional context where relevant (e.g. which variable was added, which role was changed)

## Using logs for troubleshooting

If a product is behaving unexpectedly after a change was made, the logs can help you identify what was changed and when. Filter by date or search for specific action types to narrow down the relevant entries.

Logs are retained for the duration of your subscription and for a period after cancellation.
